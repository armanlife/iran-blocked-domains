# اجرای Checker روی سرور لینوکس

این بسته checker را به صورت یک سرویس پس‌زمینه (systemd) اجرا می‌کند:

- بعد از بستن SSH به کار ادامه می‌دهد
- بعد از ری‌استارت سرور خودش دوباره شروع می‌شود
- از همان جایی که متوقف شده ادامه می‌دهد
- اولویتش از بقیه‌ی سرویس‌های سرور پایین‌تر است
- اگر جدول conntrack فایروال بیش از نصف پر شود، صبر می‌کند تا بقیه‌ی سرویس‌ها (مثلاً تماس‌های VoIP) مختل نشوند

سرور باید **داخل ایران** باشد. اینترنت داخل ایران را می‌شود این‌طور بررسی کرد: اگر جواب `10.10.34.x` بود، سرور داخل ایران است.

</div>

```bash
getent ahostsv4 facebook.com | head -1
```

<div dir="rtl">

## ۱. ساخت بسته

روی کامپیوتری که Go دارد، در پوشه‌ی `checker`:

</div>

```bash
./deploy/build.sh          # Linux / macOS / Git Bash
.\deploy\build.ps1         # Windows PowerShell
```

<div dir="rtl">

فایل `dist/domain-checker-linux-amd64.tar.gz` ساخته می‌شود (برای سرورهای ARM فایل `arm64`). این فایل را می‌شود به هر کسی داد و به Go یا هیچ برنامه‌ی دیگری نیاز ندارد. نسخه‌ی ویندوز هم در `dist/domain-checker-windows-amd64.exe` ساخته می‌شود.

## ۲. کپی روی سرور

</div>

```bash
scp dist/domain-checker-linux-amd64.tar.gz root@SERVER:/root/
ssh root@SERVER
tar -xzf domain-checker-linux-amd64.tar.gz
cd domain-checker
```

<div dir="rtl">

لیست دامنه‌ها را هم در همین پوشه بگذارید. هر خط یک دامنه، یا CSV مثل `google.com,1`.

## ۳. شروع

یک لیست ساده:

</div>

```bash
bash service.sh install mylist.txt 20
```

<div dir="rtl">

یا یک لیست رتبه‌دار، ساخته شده از رتبه‌بندی host.io و لیست قبلی پروژه. `merge` روی یک سرور با یک هسته چند دقیقه طول می‌کشد:

</div>

```bash
./checker merge -dir results/host10m -ranking host10m.csv -previous ir-blocked
bash service.sh install results/host10m 25
```

<div dir="rtl">

عدد آخر سرعت است: تعداد دامنه در ثانیه. بعد از این دستور می‌توانید SSH را ببندید.

## دستورها

| دستور | کار |
|---|---|
| `bash service.sh status` | پیشرفت، زمان باقی‌مانده و تعداد هر دسته |
| `bash service.sh logs` | دیدن لاگ به صورت زنده (با Ctrl+C از لاگ خارج می‌شوید، بررسی ادامه دارد) |
| `bash service.sh stop` | توقف. بررسی‌های در حال اجرا تمام و ذخیره می‌شوند |
| `bash service.sh start` | ادامه از همان جا |
| `bash service.sh recheck dns-timeout,connect-failed 20` | بررسی دوباره‌ی دسته‌ها، با حفظ رتبه‌ی هر دامنه |
| `bash service.sh uninstall` | حذف سرویس. نتایج باقی می‌مانند |

برای تغییر سرعت: `stop`، بعد دوباره `install` با همان لیست یا پوشه و سرعت جدید. بررسی از همان جا ادامه پیدا می‌کند.

بررسی دوباره را بعد از تمام شدن بررسی اصلی انجام دهید. بعد از بررسی دوباره، برای ادامه‌ی بررسی اصلی دوباره `install` کنید.

اگر اینترنت سرور قطع شود، checker هیچ نتیجه‌ای ثبت نمی‌کند و صبر می‌کند تا اینترنت برگردد. در لاگ نوشته می‌شود: `network is down`.

## نتایج

نتایج در `results/<نام لیست>/` ذخیره می‌شوند. همه‌ی لیست‌ها به ترتیب رتبه هستند و در طول بررسی هم به‌روز می‌شوند (لیست‌های بیش از یک میلیون دامنه هر ده دقیقه):

| فایل | محتوا | انتشار |
|---|---|---|
| `blocked.txt` | همه‌ی دامنه‌های فیلتر شده | عمومی |
| `blocked-dns.txt`، `blocked-sni.txt` | فیلتر شده با DNS یا با SNI | عمومی |
| `dns-timeout.txt`، `dns-not-found.txt`، `dns-error.txt` | خطاهای DNS | عمومی |
| `tls-failed.txt` | اتصال TLS برقرار نشد | عمومی |
| `run.json` | وضعیت، تنظیمات و تعداد هر دسته | عمومی |
| `connect-failed.txt` | اتصال به IP برقرار نشد | محلی (حجیم) |
| `not-blocked.txt` | آزاد | محلی (حجیم) |
| `checker.db` | لیست رتبه‌دار، همه‌ی نتایج با جزئیات و تاریخچه | محلی |

`.gitignore` همین پوشه فایل‌های محلی را از git بیرون نگه می‌دارد.

جستجوی رتبه، نتیجه و تاریخچه‌ی یک دامنه:

</div>

```bash
./checker find -dir results/host10m youtube.com
```

## انتخاب سرعت

محدودیت اصلی سرعت معمولاً جدول conntrack فایروال است، نه CPU یا رم. هر اتصال تا دو دقیقه در این جدول می‌ماند و اگر جدول پر شود، بسته‌های همه‌ی برنامه‌های سرور دور ریخته می‌شوند.

اندازه‌ی جدول را ببینید:

</div>

```bash
cat /proc/sys/net/netfilter/nf_conntrack_max
```

<div dir="rtl">

هر «یک دامنه در ثانیه» حدود 150 ردیف از جدول را اشغال می‌کند. برای اینکه جدول کمتر از نصف پر شود:

**سرعت مناسب = اندازه‌ی جدول ÷ 300**

| اندازه‌ی جدول | سرعت مناسب | زمان 10 میلیون دامنه |
|---|---|---|
| 8,192 | 25 | حدود 4.6 روز |
| 65,536 | 200 | حدود 14 ساعت |
| 262,144 | 500 | حدود 6 ساعت |

اگر فایل بالا وجود نداشت، فایروال conntrack ندارد و این محدودیت نیست. در آن حالت از 100 شروع کنید.

اگر سرعت را بیش از حد انتخاب کنید، checker وقتی جدول از نصف پرتر شود صبر می‌کند تا خالی شود. پس سرعت انتخابی فقط سقف است.

نتیجه‌ی تست روی یک سرور با 1 هسته، 1 گیگابایت رم و جدول 8,192 ردیفی:

| سرعت | بیشترین پر شدن جدول | CPU | رم |
|---|---|---|---|
| 20 | 2,818 (34٪) | 4٪ | 17 مگابایت |
| 50 | 5,931 (72٪) | - | - |

**ترافیک:** هر دامنه حدود 7.6 کیلوبایت ترافیک دارد، یعنی حدود 75 گیگابایت برای 10 میلیون دامنه. اگر سرور سقف ترافیک ماهانه دارد، آن را در نظر بگیرید.

**نتایج به شبکه بستگی دارند:** فیلترینگ در اپراتورها و دیتاسنترهای مختلف یکسان نیست. مثلاً `x.com` روی یک دیتاسنتر با DNS فیلتر بود و روی اینترنت خانگی با SNI. بعضی سایت‌ها هم IPهای دیتاسنتر را نمی‌پذیرند و در `connect-failed` قرار می‌گیرند.
